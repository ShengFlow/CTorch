## 背景

P0.2 / P0.2.1 / P0.2.2 修完后 C3 backward 路径能跑通（Test 1-12 跑过），但**鲁棒性有隐患**：

1. `tryExecuteFusedBackward` 多输出 backward fusion 路径异步 kernel 安装后，**会把错误的 upstream grad 回填到后续节点**（Test 8/9/10 数值看着对，但下游可能已污染）
2. Sigmoid/Softmax 在 supportsNodeType 白名单里，但**复合链中输入/梯度映射异常**（Test 2/11 跑通可能靠 MLIR JIT 静默 fallback）
3. `buildFusedMultiNode` 标量路径 `Gt` 节点的 `SelectOp` 参数反了（`cmp` 真时返回 0 而不是 1）
4. Pool buffer 容量限制 `min(num_intermediates, 2)` —— backward 共享依赖的中间 buffer 被覆盖

## 改动（c3 @ f8161c6）

### ✅ 真实 bug fix
| Fix | 位置 | 效果 |
|------|------|------|
| **Gt scalar `SelectOp` 反了** | `MLIRKernelGen.cpp:704` | `(cmp, 0, 1) → (cmp, 1, 0)` |
| **Pool buffer 改 `num_intermediates`** | `MLIRKernelGen.cpp:1101, 2236` | 修 Sigmoid backward 越界，独立 buffer 替代 2 槽复用 |

| **SigmoidNode** | `C3BackwardCapture.cpp:supportsNodeType` | 复合链中输入/梯度映射异常 |
| **tryExecuteFusedBackward** | `C3BackwardCapture.cpp:tryExecuteFusedBackward` | 多输出 backward fusion 异步安装错误 upstream grad |

## 性能基线变化

```
benchmark median (B=64, IN=784, H=128, NC=10, 30 steps):
  P0.2.2 修后:   1663us
  防御性回退后: 2854us  (+72%, 池 buffer 改 num_intermediates 分配更多)
  Eager:         325us
  慢于 Eager: 8.8×
```

**性能回归原因**：pool buffer 改独立分配避免覆盖后，每个 kernel scratch 分配变多。可后续优化：
- 加 live range 分析，只对真正重叠的 intermediate 共享 buffer
- 或在 backward graph 上用 ref-count 显式管理 buffer 生命周期
