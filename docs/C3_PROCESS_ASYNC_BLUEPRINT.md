## 1. 背景与目标

C3 当前的异步编译全部运行在 **Ctorch 主进程内部（线程级）**。RC2 的目标是把编译从主进程彻底解耦，落地为 **独立守护进程 c3d + 共享内存 IPC** 的进程级异步，实现 c3-complete-report 中设计的 v0.3.0 阶段，并为 v1.0.0+ 集群级服务预留接口。

### 1.1 现状基线（2026-09-03 实测确认，测试全绿）

- `test_c3_backward`：**12/12 PASS**（含 CrossEntropy/Softmax backward，max_diff≈7.45e-08，backward miss 归零）
- `test_c3_graph`：**115/115 PASS**
- `test_c3_compile_merged`：**10/10 PASS**；`test_c3_compile_merged_pgo`：**11/11 PASS**

当前线程级异步的实现要点（源码定位）：

| 位置 | 机制 |
|---|---|
| `C3HotPathManager.h` | 双管线异步编译：`std::async(launch::async)` 启动 Tier-1 fast / Tier-2 extreme，`pending_futures_`（`vector<future<void>>` + mutex）管理生命周期 |
| `C3Engine.cpp` | `compileAsync`/子图并行编译/watchdog 均走 `std::async` |
| `C3BackwardCapture.cpp` | 因 `std::future` 析构会阻塞等待（变相同步），改用 `std::thread + detach` 实现真后台异步 |
| `C3Engine.h` | `CompileFuture = shared_future<shared_ptr<CompiledKernel>>`；`compileAsync`/`compileMergedAsync`/`traceAndInjectAsync` 统一返回该类型；`shutdown()` 生命周期（析构自动调用，安全） |
| `PGOManager.cpp` | `std::async` 后台 PGO，集中 future 管理避免 detach UAF |

**结论：线程级异步基础设施成熟、测试稳定，是进程级迁移的正确起点。进程级守护（c3d）+ 共享内存 IPC 目前为零实现，是 RC2 的全新工程。**

## 2. 目标架构（参考 c3-complete-report v0.3.0）

```
+------------------------------- Ctorch 主进程 -------------------------------+
|  用户代码 → 表达式捕获 → 内核调度器 → 张量执行                              |
|  提交编译任务（eager 路径先返回，异步升级内核）                             |
+------------------------+----------------------+------------------------------+
                         |  共享内存 IPC（零拷贝）
+------------------------v----------------------v------------------------------+
|  SPSC 无锁环形队列（任务队列）  |  MPSC 无锁队列（结果注册表）  |  Data Arena  |
|  原子 state/processed          |  原子指针交换              |  内存池/序列化  |
+------------------------+----------------------+------------------------------+
                         |  混合等待：自旋 ~10-20µs + futex 阻塞（"无事不扰，有事秒回"）
+------------------------v----------------------v------------------------------+
|                          c3d 守护进程（独立进程，可绑核）                      |
|  任务调度器 → MLIR 管线 → LLVM JIT → 内核缓存 → 结果回写                       |
+------------------------------------------------------------------------------+
```

### 2.1 演进路线锚点

- v0.1.0 线程级异步：**已完成**（当前基线）
- **v0.3.0 进程级守护：本文档目标（RC2）**
- v1.0.0+ 集群级服务：预留（共享缓存 / 服务发现 / 分布式）

### 2.2 设计原则（保持）

1. 零可感知延迟：首见 Shape 编译一次，稳态无卡顿
2. 性能持续进化：后台编译 + 原子指针热替换
3. 崩溃隔离：c3d 崩溃不影响主进程计算
4. 资源零干扰：编译不抢占计算 CPU/内存（进程级天然更优）

## 3. 核心设计难点与决策（需 RC2 前定案）

### 3.1 【最难】跨进程内核交付

**问题**：线程级下 `compileAsync` 直接在同进程返回 `shared_ptr<CompiledKernel>`（含函数指针），跨进程后**函数指针是进程内地址，不可直接调用**。

**候选方案**：
- **A. 共享内存机器码 + 主进程 mmap**：c3d 把编译好的机器码段写入共享内存，主进程在同一地址 mmap 后取得可调用地址。要求编译为 PIC/位置无关代码，地址空间布局可复现。
- **B. 动态库交付**：c3d 每次编译产出独立 `.so/.dylib`（或写回磁盘），主进程 `dlopen/dlsym` 取得符号地址。实现简单，但引入磁盘 I/O 与加载延迟。
- **C. 混合**：稳态热内核走 A（零拷贝、快），冷路径/非常规内核走 B。

**建议**：优先评估 A（最贴合"零拷贝异步通信"原始设计），B 作为可落地的 phase 4 过渡。**本难点需在 Phase 1 前用最小可行性实验（MVE）验证地址空间可行性**，否则整套 IPC 设计会返工。

### 3.2 编译请求/图序列化

- Graph IR、CompileOptions、张量 shape/desc 需跨进程传递。
- 设计目标：Data Arena 内零拷贝序列化（偏移引用），避免每请求一次堆拷贝。
- 复用现有 RollingHash/cache key 体系作为任务去重键。

### 3.3 异步语义保持

- `compileAsync` 返回 `CompileFuture`。进程级实现需包装为同签名：主进程提交到 c3d 后立即返回 future，c3d 回写结果时通过共享内存 + 原子状态回填 future。
- 调用方代码**无需改动**（后端可插拔），这是迁移成功的关键验收标准。

### 3.4 生命周期

- c3d 启动/停止、崩溃检测与重启（熔断）、主进程退出时优雅清理。
- 参考现有 `pending_futures_` 与 `shutdown()` 的成熟模式，演进为进程级握手协议。

### 3.5 兼容与回退

- 默认线程级，进程级作为可切换后端（CMake option / 环境变量 `C3_ENABLE_PROCESS_ASYNC`）。
- 任一阶段可一键回退线程级，保证回归。

## 4. 分阶段迁移路线

### Phase 0：接口抽象（1 周）
- 把"后台编译后端"抽象为 `CompilerBackend` 接口：`ThreadBackend`（现有）/`DaemonBackend`（未来）可插拔。
- `compileAsync`/热路径触发点改为走接口。
- 验收：抽象后现有测试**零回归**（12+115+10+11 全绿），调用方 API 不变。

### Phase 1：共享内存 IPC 层（2 周）
- 实现 `SPSCQueue`（环形缓冲 + 缓存行对齐 alignas(64)）、`MPSCQueue`、`DataArena`（内存池）。
- 纯库 + 单元测试（复用 C3-Learning 08 教材思路）。
- 验收：SPSC/MPSC 高并发压测通过；缓存行对齐防伪共享验证。

### Phase 2：序列化层（1-2 周）
- Graph / CompileOptions / shape desc 的序列化-反序列化，Data Arena 内偏移引用。
- 验收：序列化往返一致；大图吞吐达标。

### Phase 3：c3d 守护进程骨架（2 周）
- 独立进程：启动/停止、信号处理（SIGTERM 优雅退出）、崩溃检测重启、CPU 绑核。
- 与主进程握手（版本对齐、初始化确认）。
- 验收：c3d 可独立启停，崩溃后主进程无感重启。

### Phase 4：端到端串通（2-3 周）
- 主进程提交 → c3d 编译 → **内核交付（先走方案 B 动态库，验证语义）** → 主进程执行。
- 先跑通一个热内核（如 MatMul+act），再逐步覆盖。
- 验收：MNIST/MLP 训练在进程级下正确性 = 线程级（逐位或 eps 内一致）。

### Phase 5：稳定性工程 + 内核交付升级（2 周）
- 多级熔断、金丝雀发布（先 1% Ofast 观察）、原子热替换、退出清理。
- 内核交付从方案 B 评估升级到方案 A（共享内存机器码）。
- 验收：长时间运行无泄漏/UAF；崩溃注入测试通过。

> 合计约 9-12 周，与 RC2（2027-02-06）窗口匹配；若从 9 月中旬开工、考虑周内碎片时间，可在寒假集中攻坚。

## 5. 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| 跨进程内核交付不可行（地址空间） | **P0** | Phase 1 前 MVE 验证；Plan B 动态库兜底 |
| IPC 端到端时延反超线程级 | P1 | 零拷贝 + 混合等待；基准阈值设 10µs 内 |
| 序列化大图开销 | P2 | Data Arena 偏移引用 + RollingHash 去重 |
| 生命周期/UAF 回归 | P1 | 复用 pending_futures_/shutdown 成熟模式 |
| 与线程级回归不一致 | P0 | 后端可插拔 + 一键回退 + 全测试门禁 |

---

## 6. 与当前线程级的关系

- **进程级是增强，不是替换**：默认线程级，进程级经 `C3_ENABLE_PROCESS_ASYNC` 开启。
- 线程级继续作为正确性参照与回退路径。
- 论文中"异步非阻塞 JIT"叙事天然承接进程级形态，可作为 RC2 后的论文/演示卖点。
